# Web認証とパスワード設定

HTTP・HTTPSは `http-auth`、Socket.IOは専用ミドルウェアを使い、どちらも同じパスワード照合・試行制限を適用します。
LAN・インターネットからは [HTTPSリバースプロキシ](reverse-proxy.md) 経由で接続してください。
Basic認証で送る資格情報はBase64であり、通信の保護にはHTTPSが必要です。

## 初回設定・追加・変更・再設定

リポジトリのディレクトリで、設定ファイルの所有者として実行します。

```sh
npm run password -- chinachu
```

`chinachu` はユーザー名です。新しいパスワードと確認用の再入力を求めます。
入力は画面に表示せず、引数・環境変数・パイプでのパスワード指定は受け付けません。
12文字以上、UTF-8で1024バイト以内にしてください。ユーザー名は空白・コロン・制御文字を含まない128バイト以内、最大16ユーザーです。
未登録のユーザー名なら追加し、登録済みならパスワードを変更します。パスワードを忘れた場合も同じコマンドで再設定できます。
保存済みハッシュが壊れた場合も再設定できます。バックアップでは、そのユーザーの壊れた認証情報だけを除去し、他ユーザーとその他の設定は維持します。
このバックアップを復元する場合は、除去されたユーザーのパスワードを再設定してからWUIを起動してください。

別の設定ファイルを指定する場合:

```sh
npm run password -- chinachu --config /path/to/config.json
```

サンプルの `wuiUsers` はパスワード未設定の `chinachu` です。初回設定が完了するまでWUIは起動しません。
保存後に **WUIを再起動** すると反映されます。再起動前は起動時に読み込んだ認証情報が有効です。
ブラウザーが旧パスワードを再送する場合は、新しいパスワードで認証し直してください。

## 旧平文設定からの移行

```sh
npm run password -- --migrate
```

旧形式の `"ユーザー名:パスワード"` を、同じパスワードでログインできるハッシュ形式へ変換します。
その他の設定は維持します。`config.json.bak` は移行前の設定をハッシュ化した内容に置き換えます。
以前に手動コピーした設定や別の場所のバックアップは対象外です。
サンプルと同じパスワードもそのまま移行されるため、設定コマンドで固有のパスワードへ変更してください。
平文設定のまま新しいWUIを起動すると、移行を案内して終了します。

## 設定画面・API

設定画面の「Web認証ユーザー」にはユーザー名と設定済み状態を表示します。
既存ユーザーのパスワードは、新しいパスワードを入力して保存すると変更できます。
空欄は現在のパスワードを維持します。入力したパスワードをJSON編集へ自動転記せず、保存成功後は入力欄を消去します。
ユーザーの追加・初回設定はCLIを使用してください。

`GET /api/config.json` と `PUT /api/config.json` の応答は、次の公開用形式です。パスワードとハッシュは返しません。
応答には `Cache-Control: no-store` を設定します。

```json
{"wuiUsers":[{"username":"chinachu","passwordSet":true}]}
```

PUTでは変更対象のユーザーにだけ `password` を追加します。`password` の省略・空文字は既存のハッシュを維持し、
`wuiUsers` 自体を省略した場合も既存の認証設定を維持します。クライアントからの `passwordHash` は拒否します。
`passwordSet` は表示用であり、認証情報を変更しません。更新競合は通常の設定APIと同じETag・revisionで検出します。
設定ファイルのJSONが壊れている場合は、秘密情報の混入や認証設定の欠落を防ぐためAPIの読み書きを拒否します。サーバー上で修復してください。

`wuiUsers: []` の明示指定は認証を無効にします。これは全経路を認証するプロキシを用意した場合の設定です。
ユーザー配列から既存ユーザーを除くと、そのユーザーは再起動後にログインできなくなります。

## 保存形式・権限・照合負荷

パスワードごとに16バイトのランダムなソルトを生成し、scrypt（N=131072、r=8、p=1）で32バイトの鍵を導出します。
`config.json` には `{ "username": "…", "passwordHash": "scrypt$131072$8$1$…$…" }` を保存します。
パラメーターは固定して検証し、異常なハッシュ形式や未設定ユーザーは起動時に拒否します。

CLI・設定APIの保存では、設定とバックアップの所有者・グループを維持します。
他ユーザーにも公開されていたファイルは0600にします。既に他ユーザーの権限がない場合だけ、元のグループ読み取り権限を維持します（0600または0640）。
所有者は読み書き可とし、グループ書き込み権限は除去します。
WUI・録画・スケジューラーを別ユーザーで実行する場合は、設定を必要とするユーザーだけを専用グループに所属させてください。
WUIには設定ファイルの読み取りと、その親ディレクトリで一時ファイルを作成・置換する権限も必要です。

ログイン照合は非同期で、同時scrypt処理はWUIプロセス全体で最大2件、1送信元IPにつき最大1件です。
1送信元IPにつき60秒で最大5回の未キャッシュ照合を許可し、成功でその送信元のカウンターをリセットします。
同じユーザー名でも別の送信元の失敗によって締め出しません。ユーザー名を変えても同じ送信元の制限を共有します。
存在しないユーザー名はscrypt処理に入る前に拒否し、既存ユーザーの照合枠やカウンターを消費しません。
未知のユーザーは照合しないため、応答時間は登録済みユーザーと異なる場合があります。
送信元IPは接続元を使います。`wuiXFF: true` の場合だけ、ループバックのプロキシから届いた単一の有効な `X-Forwarded-For` IPを使います。
プロキシはこのヘッダーを実際のクライアントIPで上書きしてください。NATなどで同じIPを使うクライアントは制限を共有します。
送信元カウンターは最大1024件を保持し、満杯の場合は最も古く使われたカウンターを除去します。
上限到達時のHTTP応答は通常の認証失敗と同じ401、Socket.IOは認証エラーです。

成功した資格情報だけを最大256件・60秒キャッシュします。キーはプロセスごとの秘密鍵によるHMACで、平文は保存しません。
キャッシュ済みの正常な要求は試行制限中も通すため、動画・静的アセットへの繰り返しアクセスでscryptを毎回実行しません。
照合の作業メモリーは2件で約256MiB必要です。制限・キャッシュはHTTPとSocket.IOで共有し、WUI再起動時に破棄します。
複数WUIプロセスを公開する場合は、プロキシ側でも全体の試行制限を適用してください。
