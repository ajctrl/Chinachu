# 一致キーワードと共通除外

予約一覧の「一致キーワード」は、予約条件をすべて満たしたルールの
`reserve_titles`・`reserve_descriptions` のうち、実際に一致したキーワードを
重複なしで表示します。表示するのは設定した文字列（正規表現）です。
キーワード条件のないルールから生成した予約では空欄になります。

共通除外はGUIから管理できます。「ルール」画面の「共通除外ルールへ」で
切り替え、「共通除外ルールを追加」で作成します。行を選択して「編集」または
ダブルクリックすると条件を変更できます。編集フォームの「有効にする」で
有効／無効を切り替え、不要なルールは選択して「削除」します。
保存後にすぐ予約へ反映したい場合は「スケジューラー実行」を使います。
ほかの画面で変更した内容は「更新」で読み込み直せます。

保存先は `excludes.json` です。`rules.json` と同じくルールの配列を保存します。
GUIのほか、ファイルを直接編集することもできます。空配列 `[]` では無効です。
たとえば、タイトルまたは説明文に「再放送」が含まれる自動予約をスキップする
`excludes.json` は次のとおりです。

```json
[
  { "reserve_titles": ["再放送"] },
  { "reserve_descriptions": ["再放送"] }
]
```

`excludes.json` がない場合だけ、旧 `config.json` の `autoExclusionRules` を読み込みます。
旧設定もなければ共通除外は無効です。GUIで初めて追加・編集・削除すると、
旧ルールを引き継いだ `excludes.json` を作成します。`config.json` 自体は変更しません。
新ファイルが存在すれば、空配列の場合も含めて旧設定より優先します。
移行後は `config.json` の `autoExclusionRules` を削除できます。
手動で移行する場合は、その配列を `excludes.json` に保存してください。
旧ルールがない新規環境では `excludes.sample.json` をコピーして使えます。
サンプルには、タイトルまたは説明文の「再放送」、タイトルと説明文の両方に
条件が一致する総集編・ダイジェスト、再放送フラグ「再」の3つの除外例があります。
すべて `isDisabled: true` なので、使いたい例をGUIで有効にするか、
ファイルの `isDisabled` を `false` に変更してください。

GUIでの更新は一時ファイルからのアトミックな置き換えで行い、直前の内容を
`excludes.json.bak` に1世代保存します。初回作成時は `config.json` の所有者・
グループ・アクセス権を引き継ぎ、以後は `excludes.json` のものを維持します。
読み取り専用の表示ではファイルを作成しません。不正な新ファイルがある場合は
旧設定には戻らずエラーにするため、ファイルを修正してください。

各要素は既存の予約ルールと同じ形式です。キーワードは正規表現で、
`normalizationForm` も適用します。タイトル・説明文それぞれの配列内は
`reserve_titles_operator`・`reserve_descriptions_operator` で AND／OR を選択でき、
省略時は OR です。タイトルと説明文の間は `reserve_fields_operator` で選択し、
省略時は AND です。放送波・時間帯などの条件は引き続き AND、ルール同士は OR です。
`rules.sample.json` にも演算子の例があります。最後の無効なルールは、
タイトルに「映画」または「劇場版」が含まれるか、説明文に「日本語」と「吹替」の
両方が含まれる番組を予約する例です。
`isDisabled` で個別に無効化できます。設定は次のスケジューラー実行時に反映します。

共通除外は予約候補を集めた後、重複・競合判定の前に適用します。一致した番組は
予約一覧に残し、録画をスキップします。「除外ルール」には、条件をすべて満たした
共通除外ルールのうち実際に一致したタイトル・説明文キーワードを表示します。
手動予約は対象外です。予約ルールにも一致する場合も手動予約を維持します。
既存の `ignore_titles`・`ignore_descriptions` は、従来どおり候補から除外します。

自動スキップを解除すると、その予約に手動解除情報を保存します。予約更新や
再起動後も再スキップせず、除外キーワードには `再放送（手動解除）` のように
表示します。除外条件が一時的に一致しなくなっても手動解除情報は維持します。
もう一度スキップすると手動解除情報を消し、自動除外に従う状態へ戻します。
この時点で除外条件に一致していなければスキップしません。

通常の手動スキップがある場合は、その予約を一覧に残し、同じ放送波・物理
チャンネル・開始時刻・終了時刻・タイトルの別サービスの自動予約を重複として
除外します。SID の大小によらず、別 ID の予約が代わりに録画されることを
防ぎます。元の予約のスキップを解除すると、通常の重複判定へ戻ります。
別サービスを明示的に手動予約した場合は、このスキップによる抑止の対象外です。
その手動予約のスキップを解除した場合も、録画対象として残します。
共通除外による自動スキップは、ほかのサービスの予約を抑止しません。
重複するサービスはまとめて判定し、スキップによる自動予約の抑止を先に
確定してから、残る録画候補を選びます。サービスの並び順で結果は変わりません。

同じ時間帯・タイトルの複数サービスが重複する場合は、手動解除した予約を
SID の大小より優先して残します。複数の予約を手動解除した場合はそれぞれを
残し、通常のチューナー競合判定を行います。別サービスが通常の手動スキップ
でも、手動解除した予約は残して録画対象とします。再スキップして手動解除情報を
消すと、再び通常の重複判定に従います。

手動解除のない自動スキップは、除外に一致しなくなれば解除します。
通常の手動スキップは除外条件によらず維持します。状態は番組タイトルではなく
予約単位で引き継ぎます。番組 ID が異なる次回放送や、ID が再利用されても
終了した前の予約と放送時間が重ならない番組には引き継ぎません。
終了前の予約は、同じ番組 ID の放送時間変更後も状態を維持します。

判定情報は `data/reserves.json` に保存します。`matchedKeywords` は一致キーワード、
`excludedKeywords` は除外キーワード、`isExcluded` は共通除外の一致、
`isAutoSkip` は自動スキップ、`autoSkipOverride` は手動解除を表します。
録画のスキップには既存の `isSkip` を使います。旧データの `isSkip` は
通常の手動スキップとして扱います。一覧表示時にルールを再判定することはありません。
